# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
pnpm install        # pnpm only (packageManager is pinned in package.json)
pnpm run dev        # Vite dev server on :3000, served under /millisalary/ (opens a browser)
pnpm run dev:host   # same, bound to 0.0.0.0 for testing on a phone
pnpm run build      # tsc -b (the only type check) + vite build into build/
pnpm run preview    # serve build/ — use this to test the service worker / install flow
pnpm run lint       # eslint over **/*.ts(x)
pnpm run deploy     # build, then gh-pages pushes build/ to the gh-pages branch
```

- There is no test suite. Verify changes in the running app; `.claude/launch.json` defines a `millisalary-dev` preview server on port 5174.
- Lint baseline: 0 errors and 1 `react-refresh/only-export-components` warning in the generated `ui/button.tsx` (standard shadcn output). Anything beyond that is a regression.
- `pnpm run deploy` (not `pnpm deploy`, which is pnpm's own workspace command) publishes to https://nalezhytyi.github.io/millisalary/ (Pages takes ~1 min to pick it up). Never `git push` or deploy without the user's explicit approval for that specific push/deploy.
- pnpm specifics: it does not run `pre*`/`post*` scripts, so `deploy` builds explicitly; install scripts only run for packages in `pnpm.onlyBuiltDependencies` (`esbuild`); and `node_modules` is strict, so every import needs a declared dependency — e.g. `workbox-window` is a devDependency because `virtual:pwa-register` imports it.
- Prettier runs `prettier-plugin-tailwindcss` 0.7.x with `tailwindStylesheet: ./src/index.css` in `.prettierrc` (needed to sort Tailwind v4 theme classes); 0.8.1 crashed intermittently with `e.charAt is not a function`.
- Commit with the repo-local git identity (`nalezhytyi`), not the global work identity. Commit messages use Conventional Commits with a lowercase scope, e.g. `fix(pwa): …`, `feat(timepicker): …`.

## Architecture

Single-page React 19 + TypeScript + Tailwind v4 + shadcn/ui (Radix) app, no router and no global state library. Everything is deployed under the `/millisalary/` base path (`vite.config.ts` `base`, manifest `scope`/`start_url`/`id`).

**State flows through one hook.** `useAppState` (`src/hooks/useAppState.ts`) owns every setting and every change handler; `App.tsx` destructures it and passes props down to presentational components. Settings persist via `useLocalStorage` (JSON in `localStorage`, keys: `monthlySalary`, `monthlySalaryCurrency`, `earningsCurrency`, `workingHoursPerDay`, `workingDays`, `payday`, `startHour`, `endHour`, `selectedPeriod` (validated with `isPeriod`, falls back to `day`), `theme`, plus `exchangeRates` (last known rate per `FROM>TO` pair, written by `useEarnings`); `background` and `isInputsCollapsed` are legacy and removed on startup by `removeLegacyStorageKeys`). Start/end times are stored as `"HH:mm"` strings and re-anchored to today on load; components and calculations work with `Date | null`, converted by `formatTimeInputValue` / `parseTimeInputValue` in `src/utils/salaryForm.ts`.

**Coupled schedule fields:** changing Start moves End forward by `workingHoursPerDay`; changing End recomputes `workingHoursPerDay` from the range; an End earlier than Start pulls Start back to it; editing hours/day moves End.

**Earnings model:** `calculateEarnings(now, settings)` in `src/utils/calculations.ts` is a pure function returning `{ hour, day, week, month, year }` (each `{ earned, total }`), `rates` (per second/minute/hour/day) and `nextPayday`; `useEarnings` calls it every 100 ms with dayjs. Business days are Mon–Fri and only count while the month has scheduled working days left (`workingDays`); a day earns `monthlySalary / workingDays` spread over the start–end window, which is anchored to today (stored times can be from an earlier day). Week = Mon–Sun with a 5-day total; year = completed months in full plus the current one; "this hour" is the part of the current clock hour inside the window. Payday is a day of month (1–31, clamped to the month length). The exchange rate is fetched from exchangerate-api.com (`src/api.ts`) whenever either currency changes and multiplies every amount; a rate only applies to the pair it was fetched for (stale responses are dropped, the same currency is always 1, and the cached `exchangeRates` entry covers reloads and offline launches). The 100 ms tick skips the state update when no number changed, and the `useAppState` handlers are `useCallback`s so the memoized sheets don't re-render with it. Formatting uses the `uk-UA` locale with `currencyDisplay: 'narrowSymbol'` (₴, $, €, zł, Kč, lei — plain `symbol` printed "грн" in Chromium but "₴" in WebKit, and the ISO code for USD) in `formatCurrency` / `formatCurrencyParts` in the same file.

**Analytics:** `initAmplitude()` runs in `main.tsx` (autocapture + session replay at 100%). `trackAmplitudeEvent` is a no-op until init finishes. User-facing handlers in `useAppState`/`useTheme` emit snake_case events: `settings_clicked` (`source: header | setup_hint`), `settings_closed` / `breakdown_opened` / `breakdown_closed` (closes carry `duration_ms`), `period_changed`, `theme_changed`, `salary_input_blurred`, `salary_currency_changed`, `earnings_currency_changed`, `workday_start_time_changed`, `workday_end_time_changed`, and `working_days_changed` / `working_hours_per_day_changed` / `payday_changed`, which fire once on blur and only if the field was edited. New settings and UI should follow that pattern. Events sent before init finishes are dropped, so don't track on first render.

**UI and theme:** the main screen is the header (round Breakdown button on the left, Settings on the right), `EarningsDial`, `StatsRow`, a `PeriodTabs` segmented control and `SetupHint` when no salary is set. Settings and Breakdown are shadcn/vaul bottom sheets (`SettingsSheet`, `BreakdownSheet`) built on the shared `Sheet` (grabber, title, Done, scrolling body; capped to the same centered `max-w-md` column as the main screen), `ListGroup` and `ListRow`; numeric settings use `NumberInput`, which keeps the typed text while focused so a field can be cleared mid-edit. `SegmentedControl` (period and appearance) is a Radix single-choice ToggleGroup, not Tabs. Colors are shadcn tokens in `src/index.css` mapped to iOS system colors (`systemGroupedBackground`, `label`, `separator`, `systemBlue`, …) for `:root` and `.dark`; there is no other palette. `useTheme` keeps `system | light | dark` in `localStorage.theme` and toggles `.dark`, `color-scheme` and the `theme-color` meta; an inline script in `index.html` applies it before first paint (keep both in sync). Native `<select>` and `<input type="time">` stay native on purpose so iOS shows its system wheels.

**shadcn:** components live in `src/components/ui/` (`components.json`, style `radix-nova`, alias `@/`). The CLI (4.22) writes `import { cn } from "cn"`, which is an unrelated npm package: after every `pnpm dlx shadcn@latest add …` run `grep -rn 'from "cn"' src/`, point those imports at `@/lib/utils` and `pnpm remove cn`.

**Components** each live in their own folder with an `index.ts` re-export and, when needed, a co-located `.css` file for things Tailwind can't express (webkit pseudo-elements, platform workarounds).

## PWA and platform quirks

- `vite-plugin-pwa` (generateSW, `autoUpdate`) builds the manifest from `vite.config.ts`; the service worker registers only in production (`main.tsx`). After asset changes, a stale SW cache can hide updates — hard reload or test via `build` + `preview`. In an installed iOS web app a new build appears on the second launch (the first launch serves the cache and installs the new worker).
- **iOS standalone:** an inline script in `index.html` adds `html.ios-standalone` when `navigator.standalone` is true. In that mode the initial containing block is a viewport shorter than the screen (812pt on an 874pt iPhone 17 Pro: screen minus status bar), anchored at the top, and WebKit clips `position: fixed` layers to it. `src/index.css` therefore makes `html` a non-scrolling shell and `body` the scroller, and switches the full-screen layers to absolute, growing them by `env(safe-area-inset-top)`: the main screen (`.app-screen`), the vaul overlay and the vaul sheet content (`[data-slot=drawer-overlay|drawer-content]`; the sheet is pinned just below the status bar because `dvh` swings between 812 and 874 there). Any new full-screen fixed layer must join that list. While a sheet is open, Radix's scroll lock sets `body[data-scroll-locked] { position: relative !important }`, which would make the 812pt `body` the sheets' containing block and clip them again — the standalone rule forces it back to static. `SettingsSheet` sets `repositionInputs={false}`: after the keyboard closes iOS keeps reporting a short visual viewport and vaul left the sheet raised; WebKit scrolls focused fields into view itself. Don't size full-height layers with `100vh`; anchor `top`/`bottom` instead, and never park a closed layer off-screen in an absolute box (it widens the document and iOS pans to it). Verified on the iOS 26 and 18.5 simulators; the comments in `index.css` explain each rule.
- **Status bar:** `apple-mobile-web-app-status-bar-style` stays `black-translucent`. On iOS 18.5 and 26 the status-bar text follows the page (dark text over the light theme, white over dark, including a manual Light/Dark override), so no runtime switching is needed. The style is captured at install time (`WebClipStatusBarStyle` in the webclip's `Info.plist`).
- **Native time input** (`TimePicker`): `appearance: none` and `min-width: 0` keep iOS from overflowing the row; `color-scheme` is inherited from `<html>` (set by `useTheme`). In dark mode the Chromium clock icon is forced white with `filter: brightness(0) invert(1)` because Chromium versions disagree on whether `color-scheme` already lightens it. On iOS 26 `<select>` opens the native popup menu and `<input type="time">` the native wheel.
- **Icons:** the master image is `public/images/money-face.png`, which is 433×480 (not square). Every square icon (`favicon.png`, `apple-touch-icon.png`, `pwa-192x192.png`, `pwa-512x512.png`) must be derived from it without stretching. Manifest icons keep ~10% transparent padding (emoji at ~80% of the canvas), because macOS draws non-squircle app icons on a plate and a full-bleed image fills it edge to edge.
- Chrome (144+) does not refresh an installed app's icon unless the manifest `icons` entries change (e.g. a new file name). Overwriting the PNGs in place only reaches new installs.
